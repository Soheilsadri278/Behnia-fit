# بهنیا فیت — وب‌سایت مربی شخصی

یک وب‌سایت تک‌صفحه‌ای (Landing Page) فارسی و راست‌به‌چپ برای مربی بدنسازی:
**تمرین شخصی حضوری در کرج (مهرشهر) + کوچینگ آنلاین**.

سایت بدون هیچ فریم‌ورک و بدون وابستگی به CDN ساخته شده؛ فقط HTML، CSS و کمی JavaScript.
همهٔ فونت‌ها و تصاویر محلی‌اند، پس سایت آفلاین هم کار می‌کند و سریع بار می‌شود.

## ۲. قبل از انتشار، این‌ها را عوض کنید

### الف) شمارهٔ واتساپ و ایمیل (مهم‌ترین مورد)
در `assets/js/main.js` بالای فایل:

```js
var CONFIG = {
  phone:     "989361701801",  // کد کشور + شماره، بدون + و بدون صفر اول
  whatsapp:  "989361701801",
  telegram:  "989361701801",
  instagram: "behniafit"
};
```

و در `index.html` این موارد را هم با `Ctrl+F` پیدا و جایگزین کنید:
`989361701801` (لینک‌های wa.me و t.me) · `+98 936 170 1801` (متن نمایشی) ·
`@behniafit` · `https://www.instagram.com/behniafit/`

> اطلاع تماس فعلی: واتساپ و تلگرام و تماس تلفنی روی `+98 936 170 1801`،
> اینستاگرام `@behniafit`، محل تمرین کرج مهرشهر، پاسخ‌گویی شنبه تا پنجشنبه ۹ تا ۱۷.

### ب) عکس‌ها
عکس واقعی مربی روی سایت نشسته است — دو برش از یک عکس:

| فایل | اندازه | نسبت | کجا استفاده می‌شود |
|---|---|---|---|
| `assets/img/trainer-hero.jpg` | ۹۰۰×۱۰۵۸ | ۴:۴.۷ | تصویر بزرگ بالای صفحه |
| `assets/img/trainer-portrait.jpg` | ۸۰۰×۱۰۰۱ | ۴:۵ | بخش «دربارهٔ من» |

اگر عکس تازه‌ای گذاشتید، همین دو نسبت را رعایت کنید؛ کادرهای سایت قوس
بالایی دارند و عکس با `object-fit: cover` برش می‌خورد. توصیه: سر شخص در
یک‌سوم بالای کادر بماند تا زیر قوس نرود. `width`/`height` را در `index.html`
هم با اندازهٔ فایل جدید هم‌تراز کنید تا صفحه نپرد (CLS).

`assets/img/og-image.png` (۱۲۰۰×۶۳۰) کارت پیش‌نمایش شبکه‌های اجتماعی است و
با همان عکس و فونت وزیرمتن ساخته شده؛ اگر عکس عوض شد، این را هم بازسازی کنید.

برای عکس‌های قبل/بعد: کلاس `frame` در `index.html` را با `<img>` جایگزین کنید.

### ج) متن‌ها
اعتبارنامه‌های مربی (کارشناسی ارشد فیزیولوژی کاربردی، مربی رسمی فدراسیون،
قهرمان فیتنس، ۵ سال سابقه) در این جاها استفاده شده و همه از یک منبع می‌آیند:

- متای `title` / `description` / Open Graph
- دادهٔ ساختاریافته `<script type="application/ld+json">` (بخش `founder`)
- کیکر بالای تیتر هیرو + نشان دایره‌ای «۵ سال» + کارت نام روی عکس
- نوار اعتبارنامهٔ زیر نوار متحرک (`.authority`)
- پاراگراف‌های بخش «دربارهٔ من» + امضا + چهار تخصص
- سؤال متداول «مدرک و سابقهٔ مربی چیست؟»
- متن فوتر

اگر سال سابقه یا عنوانی تغییر کرد، همهٔ این جاها را با هم به‌روز کنید. جای
`[کروشه]`ها هم منتظر اطلاعات واقعی است: `[نام شاگرد]` · `[نام باشگاه یا استودیو]` …
قیمت‌ها (۴ / ۸ / ۱۵ / ۳۰ **دلار**) هم عدد نمونه‌اند و باید با تعرفهٔ واقعی مربی
جایگزین شوند. واحد پول در همه‌جا دلار آمریکا است؛ برای تغییر به یورو، عددها و
کلمهٔ «دلار» در بخش `#pricing` و کارت‌های خدمات را با هم عوض کنید.

> اگر مدرک «مربی رسمی فدراسیون» شامل شمارهٔ گواهی یا نهاد صادرکننده است، افزودن
> آن (مثلاً در بخش تخصص‌ها) اعتماد را بیشتر می‌کند — ولی فقط اگر
> واقعاً قابل ارائه باشد.

### د) گوگل و سئو
در `index.html` این‌ها را با اطلاعات واقعی پر کنید:
- `https://example.com/` در `canonical` و `og:url`
- بلوک `application/ld+json` (نام، آدرس، ساعات کاری، اینستاگرام)
- `og:image` و `twitter:card`

### ه) صفحهٔ حریم خصوصی
`privacy.html` به فارسی نوشته شده و با واقعیت فعلی سایت هم‌خوان است: سرور هیچ
داده‌ای ذخیره نمی‌کند، فرم به هیچ بک‌اندی وصل نیست و هیچ کوکی تحلیلی وجود ندارد.
اگر روزی فرم سرورمحور، گوگل آنالیتیکس، پیکسل تبلیغاتی یا درگاه پرداخت اضافه
کردید، **این صفحه باید بازنویسی شود**؛ وگرنه توضیحاتش نادرست می‌شود.

> صفحات `Impressum` و `Datenschutz` آلمانی حذف شدند، چون محل تمرین به کرج منتقل
> شد و ارجاع به قانون آلمان (§ 5 DDG و DSGVO) دیگر موضوعیت نداشت.

## ۳. اجرای محلی (پیش‌نمایش)

نیازی به build و نصب پکیج نیست؛ فقط پایتون ۳ کافی است:

```bash
python3 server.py            # http://localhost:8000
python3 server.py 3000       # روی پورت دیگر
PORT=8080 python3 server.py  # یا با متغیر محیطی
```

`server.py` یک سرور کوچک توسعه است (بدون هیچ وابستگی خارجی) و چند مزیت بر
`python3 -m http.server` دارد:

- لیست‌شدن پوشه‌ها خاموش است (ساختار فایل‌ها لو نمی‌رود).
- با HTTP/1.1 و keep-alive کار می‌کند، پس بارگذاری صفحه سریع‌تر است.
- برای CSS/JS/فونت/تصویر هدر کش یک‌روزه می‌دهد و HTML را همیشه تازه نگه می‌دارد،
  بنابراین تغییر متن‌ها بلافاصله دیده می‌شود.
- آدرس‌های بدون پسوند (`/privacy`) را مثل هاست واقعی به `privacy.html` نگاشت می‌کند.

> این فایل فقط برای توسعه است و لازم نیست روی هاست نهایی آپلود شود. باز کردن
> مستقیم با دوبار کلیک (`file://`) هم کار می‌کند، ولی از طریق سرور، بارگذاری
> فونت‌ها و تست فرم به رفتار واقعی سایت نزدیک‌تر است.

### چرا CSS و JS کش نمی‌شوند؟
یک‌بار هدر `max-age=86400` برای CSS باعث شد مرورگر نسخهٔ قدیمی را کنار HTML
تازه اجرا کند و صفحه بدون استایل دیده شود (لوگوی غول‌آسا، لینک‌های آبی، دکمهٔ
با رنگ قدیمی). الان:

- `server.py` برای `.css` و `.js` هدر `no-store, must-revalidate` می‌فرستد.
- ارجاع‌ها با `?v=10` نسخه‌بندی شده‌اند؛ با هر تغییر ظاهری عدد را بالا ببرید.
- **استایل حیاتی inline** در `<head>` هر سه صفحه هست: اگر فایل اصلی دیر برسد،
  کش کهنه باشد یا بارگذاری نشود، چیدمان، رنگ برند و اندازهٔ لوگو نمی‌شکند.
- یک **watchdog** کوچک بعد از بارگذاری بررسی می‌کند که استایل واقعاً اعمال شده
  باشد؛ اگر نه، یک‌بار با پارامتر تازه دوباره بارگذاری می‌کند.

> روی هاست واقعی (Netlify/Vercel/هاست ایرانی) پسوند نسخه در `?v=` را بعد از هر
> تغییر CSS بالا ببرید، یا از هش خودکار فایل استفاده کنید.

## ۴. انتشار — GitHub Pages (بدون خرید هاست)

همهٔ فایل‌های سایت روی شاخهٔ `main` مخزن `Soheilsadri278/Behnia-fit` هستند.
فقط یک تنظیم یک‌بارهٔ دستی مانده (GitHub اجازهٔ این کار را به هیچ ابزار
خودکار یا توکن برنامه‌نویسی نمی‌دهد؛ باید از حساب خودتان انجام شود):

**Settings → Pages → Source: «Deploy from a branch» → Branch: `main` → Folder: `/(root)` → Save**

حدود یک دقیقه بعد سایت روی این نشانی بالا می‌آید:

> **https://soheilsadri278.github.io/Behnia-fit/**

بعد از آن، هر بار که روی `main` کامیت شود سایت خودبه‌خود به‌روز می‌شود.

- مخزن عمومی است و Pages از شاخهٔ `main` و پوشهٔ ریشه سرو می‌شود.
- HTTPS خودکار و رایگان است (`*.github.io`).
- هر بار که روی `main` کامیت می‌کنید، سایت خودبه‌خود چند دقیقه بعد به‌روز می‌شود.
- فایل `.nojekyll` در ریشه هست تا Pages فایل‌ها را بدون پردازش Jekyll عیناً سرو کند.
- `404.html` صفحهٔ خطای فارسی است (مسیرهای اشتباه به آن می‌رسند).

### نکته‌ای که باید بدانید: مسیرها
GitHub Pages سایت را در **زیرمسیر** `/Behnia-fit/` سرو می‌کند، نه ریشهٔ دامنه.
همهٔ ارجاع‌های داخلی نسبی‌اند (`assets/css/style.css`) و درست کار می‌کنند، ولی
سه جا **ناچاراً آدرس مطلق** دارند و اگر روزی دامنهٔ اختصاصی گرفتید باید عوض شوند:

| کجا | مقدار فعلی |
|---|---|
| `index.html` → `canonical` و `og:url` | `https://soheilsadri278.github.io/Behnia-fit/` |
| `index.html` → `og:image` | `.../Behnia-fit/assets/img/og-image.png` |
| `index.html` → JSON-LD `"url"` | `.../Behnia-fit/` |
| `404.html` → مسیر لوگو و دکمهٔ بازگشت | `/Behnia-fit/...` |

`og:image` باید مطلق باشد؛ وگرنه واتساپ و تلگرام پیش‌نمایش لینک را نشان نمی‌دهند.

### اگر بعداً هاست و دامنهٔ اختصاصی خریدید
۱. همین فایل‌ها را روی هاست آپلود کنید (هیچ build step لازم نیست).
۲. چهار مورد جدول بالا را با دامنهٔ جدید جایگزین کنید.
۳. در GitHub → Settings → Pages، دامنهٔ جدید را در Custom domain بگذارید.
۴. صفحهٔ ۴۰۴ را هم با مسیرهای ریشه‌ای جدید (`/assets/...`) به‌روز کنید.

### گزینه‌های دیگر (اگر لازم شد)
| گزینه | هزینه | نکته |
|---|---|---|
| **GitHub Pages** (فعلی) | رایگان | HTTPS خودکار، بدون build |
| **Netlify / Vercel** | رایگان | پوشه را drag & drop کنید؛ دامنهٔ اختصاصی راحت‌تر |
| **هاست ایرانی (ایران‌سرور، لیارا …)** | ارزان | برای مخاطب داخل ایران معمولاً سریع‌تر و پایدارتر |

> ⚠️ **دسترسی از داخل ایران:** برخی کاربران ایرانی به `github.io` دسترسی
> مطمئنی ندارند و ممکن است صفحه دیر باز شود یا اصلاً باز نشود. اگر بهنیا یا
> مشتری‌هایش از ایران باز می‌کنند، تست کنید؛ اگر مشکل داشت، همان فایل‌ها را
> روی یک هاست ایرانی بگذارید — کد هیچ تغییری لازم ندارد.

## ۴٫۵. حساب کاربری و پنل مربی

سایت حالا بخش حساب کاربری دارد: شاگرد ثبت‌نام می‌کند، برنامه می‌خرد و
برنامه‌هایش را در حساب خودش می‌بیند. مربی در پنل، سفارش‌ها را تایید و
برنامه را برای شاگرد ثبت می‌کند.

**با هر برنامهٔ جدید، برنامه‌های قبلی حذف نمی‌شوند.** این یک تعهد طراحی است،
نه یک قابلیت جانبی: هیچ دستور `DELETE` روی جدول برنامه‌ها در کل کد وجود ندارد.

> ⚠️ **این بخش روی GitHub Pages کار نمی‌کند.** Pages فقط فایل سرو می‌کند و
> نمی‌تواند ثبت‌نام، رمز و دیتابیس را نگه دارد. صفحه‌های `login.html`،
> `account.html` و `admin.html` به `server.js` نیاز دارند.
> راهنمای کامل سرور و استقرار: **[`ACCOUNTS.md`](ACCOUNTS.md)**

### اجرای محلی
```bash
cp .env.example .env   # مقادیر را پر کنید
node server.js         # http://localhost:8000
```
پیش‌نیاز: Node نسخهٔ ۲۲٫۵ یا بالاتر. هیچ پکیج npm لازم نیست.

## ۸. لوگو و هویت بصری

رنگ اصلی برند **سرمهٔ `#14234B`** است که مستقیماً از لوگو گرفته شده؛ کل پالت سایت
(`--brand`, `--brand-deep`, `--brand-soft`) با همین رنگ هم‌راستا شده است.

| فایل | کاربرد |
|---|---|
| `assets/img/logo-source.png` | فایل اصلی لوگو (مرجع) — دست نزنید |
| `logo-mark.png` | مونوگرام سرمه‌ای، شفاف — هدر سایت |
| `logo-mark-light.png` | مونوگرام کرم، شفاف — روی پس‌زمینهٔ تیره |
| `logo-full.png` | لاک‌آپ کامل سرمه‌ای (مونوگرام + وردمارک + تگ‌لاین) |
| `logo-full-light.png` | لاک‌آپ کرم — فوتر تیره |
| `favicon.png` / `apple-touch-icon.png` / `icon-512.png` | فاوآیکون و آیکون اپ |
| `og-image.png` | تصویر پیش‌نمایش در شبکه‌های اجتماعی (۱۲۰۰×۶۳۰) |

نسخه‌های شفاف با اسکریپت `tools/make-logo-assets.sh` ساخته می‌شوند (نیاز به
ImageMagick). اگر لوگو تغییر کرد، فایل اصلی را جایگزین کنید و همان اسکریپت را
اجرا کنید تا همهٔ نسخه‌ها بازسازی شوند:

```bash
./tools/make-logo-assets.sh
```

## ۵٫۵. نوار متحرک چطور بی‌خالی می‌ماند

این نوار یک تلهٔ کلاسیک دارد و سه باگ هم‌زمان داشت:

1. **جهت RTL**: در صفحهٔ راست‌به‌چپ، فلکس محتوا را از راست می‌چیند. انیمیشن
   `translateX(-50%)` محتوا را به چپ می‌برد و **سمت راست نوار خالی می‌ماند**.
   راه‌حل: `direction: ltr` روی `.ticker` (متن فارسی با bidi درست رندر می‌شود).
2. **گروه‌های نامساوی**: دو نیمهٔ نوار باید *عیناً* یکسان باشند، وگرنه پرش دیده
   می‌شود. JS یک گروه مرجع می‌سازد و دقیقاً کپی می‌کند.
3. **نوار باریک‌تر از صفحه**: اگر یک گروه از عرض صفحه کوتاه‌تر باشد، در لحظه‌ای
   از چرخه فضای خالی ظاهر می‌شود. JS آیتم‌ها را تا پوشش
   `عرض صفحه × ۱٫۲ + ۱۶۰px` تکرار می‌کند و بعد کپی می‌سازد.

سرعت انیمیشن از عرض واقعی محاسبه می‌شود (~۷۰ پیکسل بر ثانیه) تا در موبایل و
دسکتاپ یکسان حس شود. بدون جاوااسکریپت هم یک گروه دوم ایستا در HTML هست تا
حلقه بی‌پرش بماند.

## ۶. نکته‌های طراحی که عمداً رعایت شده

- **موبایل‌فرست**: بیش از ۷۰٪ بازدید مربیان از موبایل است؛ دکمه‌ها بزرگ و نوار ثابت پایین.
- **یک CTA اصلی** («مشاورهٔ رایگان») که در هدر، هیرو، وسط صفحه و پایان صفحه تکرار می‌شود.
- **قیمت شفاف**: پنهان‌کردن قیمت باعث می‌شود مخاطبِ علاقه‌مند خودش را حذف کند.
- **بدون عکس استوکِ آدم‌ها و بدون نظر جعلی**: اعتماد با محتوای واقعی ساخته می‌شود.
- **راست‌به‌چپ درست**: بدون `letter-spacing` روی متن فارسی، اعداد فارسی برای شماره‌گذاری،
  لاتین‌نویسی‌ها با `dir="ltr"` جدا شده‌اند.
- **دسترس‌پذیری**: کنتراست کافی، `aria-expanded` برای منو و آکاردئون، `focus-visible`،
  احترام به `prefers-reduced-motion`، و لینک پرش به محتوا.
- **بدون وابستگی خارجی**: فونت و تصویر محلی؛ نه رد شدن IP به گوگل، نه مشکل GDPR فونت.
